# 营销 KV 智能生图工具项目汇报

> 从一句简单需求，到有设计判断、有参考约束、可沉淀复用的营销视觉生产链路。

## 一、项目摘要

我们做的不是一个“输入一句话、碰运气出图”的页面，而是一套把设计师工作拆成可执行步骤，并让真实参考图进入生成接口的营销 KV 工作台。

当前版本已经完成：

**需求输入 → Brief 理解 → 创意判断 → 参考匹配 → 设计大纲 → 美术预检 → 结构化 Prompt → 参考图随 Prompt 进入模型 → 成图 → 资产沉淀、拆分与复用**

在这条主链路之外，系统还跑通了风格持续扩充、外部灵感搜索保存、素材回流生成、用户上传图引用、兜兜 IP、多种固定图层和生成资产管理等闭环。

---

## 二、背景：为什么做这个工具

营销 KV 的难点不只是“把画画出来”。

真正决定成片质量的，是对业务信息的取舍、创意概念、主体关系、镜头构图、文字层级、参考图用途以及最终执行约束。

业务和运营同学经常只能提供一句简短需求，例如：

> 帮我生成一张标题为“冰雪温泉季”的竖版海报。

但设计师拿到这句话后，还需要继续判断：

- 哪些信息必须出现，哪些信息不能擅自补充；
- 面向什么人群，要传递什么感受；
- 主体是什么，主体占多大；
- 用什么创意概念把“冰雪”和“温泉”连接起来；
- 标题放在哪里，用什么样式；
- 画面采用平视、俯拍还是强透视；
- 哪张参考图控制版式，哪张控制风格，哪张控制角色；
- 最终如何保证文字、产品、品牌和固定图层不出错。

如果把原始需求直接丢给生图模型，偶尔会得到不错的结果，但更多时候依赖运气，主要存在四个问题。

### 1. 输入天然不完整

用户通常只给活动名称和一句画面描述。模型容易自动新增人物、品牌、英文、卖点、价格或无关道具。

### 2. 一步生图不可控

Prompt 写得很长，也不代表模型真的理解了字体、版式、风格和元素参考图分别应该控制什么。

### 3. 设计经验难以复用

优秀案例、风格图、元素图和设计方法散落在个人文件夹中。下一次做类似需求时，仍然要从头寻找和判断。

### 4. 生成结果难以继续修改

一步出图对非设计师很方便，但设计师接手后缺少可拆分、可替换和可复用的中间资产。

因此，这个工具的目标是：

- 降低输入门槛，用户不需要先学会写专业 Prompt；
- 在生图前加入真正的创意和设计思考；
- 让参考图按明确职责约束模型，而不是只作为氛围图片；
- 让素材、风格、案例和生成结果持续沉淀；
- 同时服务业务、运营和设计师，而不是只服务一次性出图。

---

## 三、产品定位

这是一个面向营销活动视觉的：

**设计推理 + 参考图约束 + 图像生成 + 资产沉淀的一体化工作台。**

它不以替代设计师为目标，而是把原来只存在于设计师脑中的步骤显性化：

- 业务和运营能够更快得到接近可用稿的第一版；
- 设计师接手时，可以看到清楚的 Brief、创意、参考依据和 Prompt；
- 团队可以逐步沉淀自己的设计方法、案例和视觉知识。

## 四、完整生图策略与算法逻辑

## Step 1：读取用户输入

目前支持的输入包括：

- 主标题，可为空；
- 副标题，可为空；
- 活动时间，可为空；
- 自然语言画面描述；
- 输出比例；
- 风格预设；
- 多张用户上传图片；
- 通过 `@图1` 等方式说明图片用途；
- 是否添加兜兜 IP；
- 是否叠加左上角 Logo；
- 是否叠加右下角活动搜索框。

系统不把所有字段都视为必填项。用户没有提供的内容，不应在后续 Prompt 中自动补充。

## Step 2：Brief 理解

Brief 节点只负责确认用户到底说了什么，不急于画画。

它会把信息分成两类：

### 硬约束

例如：

- 主标题必须是“冰雪温泉季”；
- 画幅必须是 3:4；
- 用户上传的产品图是唯一产品主体；
- 用户没有提供英文，不能自动生成英文；
- 用户未开启 Logo 和搜索框，不得出现对应图层。

### 合理推断

例如：

- 用户写“清爽夏日”，可以推断为明亮、轻盈、有留白；
- 但不能推断出折扣、价格、品牌或活动卖点。

这样做的目的是防止模型把自己的想象误当成用户需求。

## Step 3：创意判断

系统会读取：

- 当前风格的 `preset.md`；
- 12 张创意方法卡；
- Good Case 和 Bad Case；
- 用户 Brief；
- 当前画幅和上传参考图。

它必须先提出 3 个差异化创意方向，再进行自我评估，淘汰 2 个并选择 1 个。

评估维度包括：

- 是否完整覆盖主题；
- 是否有明确记忆点；
- 是否适合当前画幅；
- 主体是否足够清楚；
- 是否容易落地；
- 是否存在视觉割裂或信息拥挤。

### 示例：冰雪温泉季

**方案 1：纯滑雪场景**

只表现滑雪，缺失温泉主题，无法覆盖双内容，淘汰。

**方案 2：左右分割构图**

左边滑雪、右边温泉，画面割裂，竖版信息流阅读感较差，淘汰。

**方案 3：纵深雪景小镇**

顶部为标题，中景是滑雪角色和温泉角色，远景包含雪地小镇、缆车和山体。冰雪和温泉在同一场景中成立，层次完整，适合竖版，最终选定。

系统最终输出的不只是“风格关键词”，而是：

- 核心创意概念；
- 视觉载体；
- 冲突或趣味点；
- 记忆符号；
- 前景、中景、背景的草图分层；
- 文字区与画面区的关系。

## Step 4：生成参考图检索意图

系统根据选定创意判断需要哪些参考证据。

当前主要参考类型包括：

| 参考类型 | 主要控制内容 |
|---|---|
| 整合版式 | 主标题、副标题、时间的样式和比例；信息区、主画面区和留白区；对齐与阅读顺序；参考图已有装饰 |
| 风格质感 | 整体美术语言、完成度、材质、光影和画面气质 |
| 元素主体 | 主体或道具的造型概括、比例、边缘和材质处理 |
| 角色 | 角色比例、轮廓、动作重心和运动方向 |
| 用户上传图 | 产品或人物身份、结构、轮廓、包装比例和可见识别特征 |
| 兜兜 IP | 兜兜的固定造型、视角和与当前场景匹配的动作 |

## Step 5：参考图匹配与选择

参考图不再只做随机抽取。

系统先做规则筛选，再进行语义排序。

主要依据包括：

- 横版或竖版；
- 是否支持主标题、副标题和时间；
- 标题字数和预计行数；
- 信息槽位；
- 主视觉区域的位置；
- 主题、场景、动作和材质关键词；
- 参考图的可用标签；
- 当前创意需要的视觉证据。

质量模式下，还可以对候选参考图增加 LLM 重排。

每张入选参考图都需要记录：

- 为什么选择这张图；
- 这张图用于参考什么；
- 哪些内容禁止复制。

## Step 6：整合版式策略

当前版式策略已经从“字体参考图、日期参考图、排版参考图分别控制”升级为“整合版式参考”。

一张整合版式参考同时控制：

- 主标题、副标题和时间的字体气质；
- 三者的字号比例；
- 行数与组合轮廓；
- 对齐轴；
- 信息间距；
- 标题区、主画面区和留白区的位置与面积；
- 参考图原有的装饰系统。

具体规则如下：

1. 参考图中的主标题、副标题和时间替换成用户输入；
2. 原参考图中的品牌、版权和业务文案删除或替换；
3. 参考图中已有的引号、框线、标签、角标、下划线、色块和装饰符号需要保留；
4. 参考图中已有的英文眉题等非业务装饰文字原样保留，不改写；
5. 参考图没有的装饰和英文不得额外发散；
6. 白色或空白区域表示主视觉生成区，不代表最终背景必须是白色；
7. 文字颜色不跟随参考图，而是根据本次画面重新选择；
8. 副标题和活动时间与主标题保持同一颜色系统；
9. 对齐方式依据参考图和本次文字长度决定，不能默认全部左对齐。

整合版式对文字和区域关系的优先级，高于风格、元素和角色参考。

## Step 7：生成设计大纲

系统把创意方案和参考证据转换成可执行的设计参数。

设计大纲包括：

- 整体视觉关键词；
- 整体色彩方向；
- 主视觉主体；
- 主体占画面的比例；
- 主体和辅助元素的关系；
- 信息层级；
- 背景；
- 材质；
- 光影；
- 镜头；
- 构图；
- 前中后景；
- 标题区和主画面区的避让关系。

它相当于生图前的“画面施工图”。最终 Prompt 只能在这份大纲范围内展开。

## Step 8：美术预检

正式生图前，系统会进行一次美术总监式检查。

检查内容包括：

- Brief 是否被完整覆盖；
- 创意是否有记忆点；
- 主体是否明确；
- 主体比例是否合理；
- 版式是否适合当前比例；
- 参考图是否有充分证据；
- 标题和主体是否冲突；
- 留白是否足够；
- 是否存在模型无法执行的复杂要求；
- 是否添加了用户未提供的信息。

发现问题时，只做最小修补，避免整套方案被再次发散。

## Step 9：生成结构化 Prompt

最终 Prompt 采用结构化章节。

重要原则是：

- 只有有来源的信息才写；
- 用户没有提及的部分可以不写；
- 不自动增加无关英文、品牌、人物、产品、卖点、价格或说明；
- 明确参考图顺序和每张图的职责；
- 明确用户上传图的主体身份约束；
- 明确整合版式的文字和区域规则；
- 明确风格、元素和角色参考不得互相越权。

## Step 10：真实参考图进入生图接口

这是整套链路最关键的原则之一：

**最终生成不能只使用 Prompt。**

系统会把以下内容一起提交给 `gpt-image-2`：

- 最终结构化 Prompt；
- 整合版式参考图；
- 风格参考图；
- 元素参考图；
- 角色参考图；
- 用户上传主体图；
- 兜兜 IP 姿态参考图；
- 其他明确被用户指定的参考图。

因此，参考图不是只在文字中被提到，而是模型实际收到了图片。

## Step 11：主体身份保护

如果用户上传产品或人物图并说明它是主体，这张图就是主体身份的最高依据。

系统要求保留：

- 产品品类；
- 外形轮廓；
- 零件结构；
- 包装比例；
- 材质；
- 可见品牌识别；
- 人物主要身份特征。

只允许改变：

- 场景；
- 风格；
- 角度；
- 光影；
- 构图。

例如，用户上传一瓶洗衣液并写“产品为图 1”，系统必须生成这瓶洗衣液，不能将其替换成手机或其他相似商品。

## Step 12：兜兜 IP 逻辑

用户开启兜兜 IP 后：

- 兜兜必须出现在画面中；
- 如果用户已有明确主体，兜兜作为辅助角色；
- 如果用户没有其他主体，或明确说兜兜是主体，兜兜成为主视觉；
- 系统根据设计判断，从三视图和多姿态库中选择合适参考；
- 可以传入多张兜兜参考图；
- 兜兜禁止出现手、胳膊和嘴巴；
- 角色动作和神态必须与场景产生呼应。

## Step 13：固定图层后处理

Logo 和右下角活动搜索框不是由模型生成，而是在成图后叠加真实素材。

两者均为可选项，默认关闭。

### Logo

- 浅色背景使用深色版；
- 深色背景使用白色版；
- 左边距 40px；
- 顶部 40px；
- 宽度 200px，等比缩放。

### 活动搜索框

- 浅色和深色背景使用对应素材；
- 宽度 295px，等比缩放；
- 右边距 44px；
- 底部 22px；
- 白色椭圆区域填写活动名称；
- 使用 DouyinSansBold 字体；
- 文字水平、垂直居中。

## Step 14：速度和质量模式

默认快速模式将 Brief、基础设计、检索和预检尽量放在本地执行，把网络调用集中在：

- 创意规划；
- Prompt 优化；
- 最终生图。

目标是将一次完整生成控制在 3 分钟内。

质量模式可以打开：

- 更多 LLM 节点；
- 参考图 LLM 重排；
- 生成后质量评审；
- 一次有明确修改方向的自动重试。

页面使用 SSE 流式返回状态，Brief、设计判断、Prompt 和生图进度会逐步展示，避免用户长时间看到空白页面。

- 主标题、副标题、活动时间、画面描述和比例输入；
- 多图上传；
- `@图片` 引用；

- 活动搜索框开关；

- 三方案发散；

当前分类包括：

## 5. 设计灵感搜索

- 来源回退；

- 最新内容倒序展示；
- 保存用户原始输入、上传图和最终成图；
- 删除资产；
- AI 拆分标题层和背景层；
- 下载拆分包。

## 六、已经跑通的闭环

### 1. 需求到成图

用户输入自然语言需求，系统完成 Brief、创意、参考、设计、预检和 Prompt，并携带真实参考图完成生图。

### 2. 灵感到素材

用户从 Pinterest 或 Behance 搜索设计案例，选择后保存到素材库。

### 3. 素材到生成

素材详情页可以直接“用作参考图”回到生成页，也可以“做同款”，将详细描述带入画面输入框。

### 4. 风格文件夹到首页预设

团队按约定目录准备图片和描述文件，通过风格页面上传和配置，新风格即可出现在首页。

### 5. 生成到资产

生成结果自动进入资产页，可继续查看、下载或删除。

### 6. 资产到可编辑结果

AI 可以从成图中分离标题文字层和清理后的背景层，形成可继续加工的拆分包。

### 7. IP 选择到实际生成

用户选择兜兜后，系统进行角色定位、姿态匹配和多图引用，最终把兜兜参考图和角色约束实际传给模型。

## 七、当前价值

### 对业务和运营

- 不需要掌握专业设计语言；
- 可以快速获得更完整的第一版；
- 能看到系统为什么这样设计，而不只是等一张图。

### 对设计师

- 可以查看 Brief、创意判断和参考依据；
- 用户上传主体和版式规则更明确；
- 生成结果可沉淀、可拆分、可继续修改。

### 对设计团队

- 创意方法、正反案例和参考素材能够积累；
- 新风格可以由团队自行扩充；
- 设计经验开始从个人经验变成团队可复用知识。

## 八、当前边界

1. 图像模型仍具有概率性，复杂中文、细节装饰和版式的像素级复刻无法保证一次完全准确。
2. 整合版式是当前重点优化项。策略和真实图片传递已经完成，但字体风格、字号比例、对齐和细节装饰仍需扩大评测。
3. 默认快速模式减少模型调用；开启生成后评审和自动重试会增加等待时间与成本。
4. Pinterest 和 Behance 当前为公开搜索验证方案，生产化仍需处理接口合规、版权、限流和来源授权。
5. 当前为本地工作台原型，正式上线还需要账户权限、任务队列、并发控制、监控告警、成本统计和数据库治理。

## 九、下一阶段建议

### P0：建立整合版式评测集

重点评价：

- 标题字形相似度；
- 主副标题和时间比例；
- 对齐关系；
- 原有装饰保留；
- 无关文字增生；
- 文字区和主体区避让。

目标是让“参考图真的有用”成为可以量化的结果。

### P0：扩充案例和方法

- 增加更多 Good Case 和 Bad Case；
- 为不同主题、人群、活动类型建立案例覆盖；
- 增加创意方法卡的适用条件和禁用条件。

### P1：让参考匹配逐步可学习

记录：

- 每次候选参考图；
- 最终选择；
- 选择原因；
- 生成结果；
- 人工评分；
- 重新生成原因。

后续可以从规则排序逐步升级为基于历史反馈的排序。

### P1：完善稳定性和耗时监控

- 建立任务队列；
- 记录各节点耗时；
- 设置超时和重试；
- 记录模型调用成本；
- 保证默认链路尽量控制在 3 分钟内。

### P2：加强生成后编辑

- 文字替换；
- 局部重绘；
- 更多图层拆分；
- 与 Figma 等设计工具衔接。

## 十、汇报结论

这个项目目前最有价值的成果，不只是“能生成一张图”。

更重要的是，它已经把需求、创意、参考、生成和资产连接成一条可以继续被团队训练和扩充的工作流。

下一阶段的重点，是用更系统的案例、标签和评测，把“偶尔看起来不错”推进到“稳定达到生产可用”。
